# Phase 2 Steps 1–3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver embedding providers, reproducible batch metadata/startup compatibility, and persistent vector/full-text chunk indexes, with one guide per step.

**Architecture:** A lazy provider layer supplies pinned BGE local ONNX or hosted HTTP embeddings. Model-aware chunking retains citation offsets. Atomic indexing stores documents, batches and chunks; API startup checks schema/model compatibility without loading inference.

**Tech Stack:** Python 3.12, tokenizers/Hugging Face Hub, optional ONNX Runtime, NumPy, HTTPX, SQLAlchemy/asyncpg, pgvector, Alembic, PostgreSQL 16, pytest/Ruff/mypy.

**Spec:** `docs/superpowers/specs/2026-11-17-phase-2-steps-1-3.md`

## Global Constraints

- Preserve `embed_document.py`, `embed_query.py`, and existing user `runGuide.txt` changes.
- Same pinned BGE model/revision and 384 dimensions for documents and queries; never silently truncate or mix embedding spaces.
- Existing Phase 1 splitter defaults and CLI behavior remain compatible.
- No public ingestion/search routes, steps 4–5, remote push or publication.
- User opted out of permission questions; continue inline on existing phase-2 branch.

## Review Focus

- Unicode and protected atomic Markdown exceeding BGE limits must retain source offsets or fail explicitly, never silently lose text.
- Hosted malformed/reordered responses, failed HTTP and zero/nonfinite vectors must not corrupt an index or expose credentials/text.
- Database startup must reject dimension/model mismatch while preserving retry on ordinary outages.
- Concurrent indexing must not mix models or leave partial document/batch/chunk rows.
- Provider imports and health startup must not load local weights or require an API call.
